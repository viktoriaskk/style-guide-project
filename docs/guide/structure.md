# Структура документов

## Инструкция

**SG-12.** В инструкции используйте разделы **Перед началом**, **Порядок действий**,
**Результат** и **Если возникла проблема**. После заголовка страницы кратко объясните цель
и укажите роль. Дополнительные операции оформляйте отдельными разделами после результата.

**SG-13.** В условиях укажите доступ, роль и ограничения, которые могут помешать задаче.
Предупреждение о потере записи размещайте перед отменой, а не после неё.

**SG-14.** Нумеруйте последовательность действий. Проверка результата должна содержать
наблюдаемый признак: статус, сообщение или изменившийся список.
Формулировка «Готово» сама по себе не подтверждает успех.

**SG-15.** Для ошибки опишите признак, возможную причину и следующее действие.
Различайте подтверждённую причину и предположение. При неизвестном результате
операции сначала предложите проверить состояние, затем повторить действие.

## Справочная статья

**SG-16.** Справочная статья содержит назначение, определения, ограничения и связанные материалы.
Используйте таблицу для однотипных характеристик, но не помещайте длинную инструкцию в ячейку.

## Заголовки и имена файлов

**SG-17.** Один файл — одна страница с одним заголовком H1. Уровни H2 и H3 не пропускайте.
Заголовок называет задачу или предмет без точки в конце.
Имена файлов пишите строчными латинскими буквами через дефис, например `student-booking.md`.

Оба типа документов должны быть понятны без чтения предыдущей страницы сайта.
Связанные материалы давайте именованными ссылками.
