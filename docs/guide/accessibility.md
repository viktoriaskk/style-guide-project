# Доступность текста

Раздел помогает читать инструкции с экранным диктором, с клавиатуры,
на небольшом экране и без различения цветов. Правила дополняют SG-07 и SG-20.
Они относятся к документации и не подтверждают доступность ещё не реализованного сервиса.

## Понятные действия

**SG-33.** Описывайте действие через название элемента и цель.
Не используйте цвет, форму или расположение как единственный ориентир.
Например, вместо «нажмите зелёную кнопку справа» пишите «Нажмите **Записаться**».
Название остаётся понятным при изменении расположения элементов.

**SG-34.** Незнакомое понятие объясняйте при первом употреблении или давайте
ссылку на словарь. Не используйте оценочные выражения «очевидно», «просто» и «как всем известно».
Успешность действия зависит от ясности инструкции, а не от предполагаемого опыта читателя.

## Заголовки и ссылки

**SG-35.** Стройте иерархию H1–H2–H3 без пропусков; не заменяйте заголовок полужирным абзацем.
Название должно объяснять содержание раздела вне контекста страницы.
Это позволяет перемещаться по заголовкам с помощью вспомогательных технологий.

**SG-36.** Ссылка должна быть понятна сама по себе.
Используйте «Инструкция по отмене записи», а не «Нажмите здесь».
Если ссылка ведёт на скачивание, укажите формат файла и, если известен, размер.
Не открывайте новое окно без необходимости и предупреждения.

## Изображения

**SG-37.** Содержательное изображение сопровождайте альтернативным текстом,
который передаёт важный для задачи смысл. Не начинайте его со слов «картинка» или «изображение».
Для снимка подтверждения подходит текст: «В разделе “Мои записи” консультация
имеет статус “Запись подтверждена”». Он объясняет результат, а не перечисляет цвета.

**SG-38.** Шаги и важные данные должны быть доступны текстом рядом с иллюстрацией.
Не размещайте единственную инструкцию внутри снимка экрана.
Для сложной схемы добавьте текстовое описание порядка действий.
Декоративное изображение не добавляет сведений: после его удаления смысл и порядок действий сохраняются.
Если изображение передаёт статус, данные или действие, применяйте SG-37.
Для декоративного изображения используйте HTML с пустым атрибутом `alt`; сам атрибут не удаляйте.
Пример шаблона: `<img src="decoration.png" alt="">`. Имя файла замените на путь к реальному ресурсу.
В описании PR объясните декоративную роль изображения; рецензент проверяет это обоснование
и отсутствие потери смысла. Отдельное согласование вне PR не требуется.
Декоративные изображения в текущих примерах не используются.

## Таблицы и визуальное оформление

**SG-39.** Таблица содержит заголовки колонок и сохраняет смысл при последовательном чтении.
Не объединяйте ячейки ради оформления. Если таблица неудобна на узком экране,
замените её списком либо обеспечьте доступную горизонтальную прокрутку.
Выбирайте список, если записи читаются независимо и сравнение по колонкам не нужно.
Сохраняйте таблицу, когда сопоставление нескольких признаков помогает решить задачу.
Проверьте её на узком экране без мыши: клавишей Tab перейдите к области прокрутки,
убедитесь, что фокус виден, стрелками просмотрите все колонки, затем Tab выйдите из области.
Все значения и заголовки должны оставаться доступными; обрезание данных и ловушка фокуса недопустимы.
При необходимости разработчик темы добавляет контейнеру `tabindex="0"`, понятное доступное имя
и видимый стиль фокуса. Проверяйте результат в собранном сайте, а не только в Markdown.

**SG-40.** Смысл не должен зависеть только от цвета. Указывайте статусы словами.
После изменения темы проверьте читаемость текста, различимость ссылок,
видимый фокус клавиатуры и работу страницы при увеличении масштаба до 200%.
Для обычного текста ориентир контраста — не ниже 4,5:1,
для крупного — 3:1 согласно WCAG 2.2, критерию 1.4.3.
Крупный текст — не менее 18 pt (24 CSS px) обычного начертания или 14 pt
(примерно 18,67 CSS px) полужирного начертания. Для меньшего текста используйте порог 4,5:1.
Размер и начертание берите из вычисленных стилей браузера. Для измерения контраста
возьмите фактические цвета текста и фона из этих стилей и введите их в анализатор контраста,
например WebAIM Contrast Checker. При прозрачности учитывайте итоговый цвет после наложения;
при неоднородном фоне проверяйте наименее контрастный участок. Повторите проверку
для светлой и тёмной темы и состояний ссылки. Зафиксируйте страницу, элемент, тему,
цвета, размер, начертание и полученное отношение. Не округляйте результат вверх до порога:
4,49:1 не проходит требование 4,5:1.
Это проверяемый ориентир, а не заявление о полном соответствии сайта WCAG.

## Проверка на примерах

В [инструкции студента](../examples/student-booking.md) действие задаётся названием
**Записаться**, а успех — текстовым статусом. В [инструкции преподавателя](../examples/teacher-schedule.md)
статусы **Свободен**, **Занят** и **Отменён** названы словами.
В обеих инструкциях есть заголовки второго уровня, именованные ссылки и таблицы с заголовками.
Иллюстраций нет, поэтому SG-37–SG-38 проверяются на примере формулировки выше,
а не на несуществующих снимках сервиса.

Партнёру по ревью нужно оценить применимость этих правил к текстам
и предложить уточнения, если критерий нельзя проверить однозначно.
